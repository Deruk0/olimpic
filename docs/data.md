# База данных и демо

PostgreSQL и локальный PGlite разворачиваются по общей [схеме](../lib/schema.sql). Для первой установки используйте пустую PostgreSQL или новый каталог PGlite. При запуске приложение создаёт отсутствующие объекты схемы.

## Связи и данные

- В `accounts` есть две роли, `teacher` и `student`. Предмет хранится в `teacher_profiles`.
- `teacher_students` хранит пары преподаватель–ученик. Одна пара встречается один раз, число связей с каждой стороны свободное. Одноразовое приглашение может содержать преподавателя. Вход по коду подтверждает связь. Отвязка в профиле удаляет только пару. Выданные уроки и текущие сдачи остаются у участников занятия.
- Материалы библиотеки, файлы и назначения принадлежат преподавателю через `teacher_id`. Выданное ДЗ хранится как отдельная запись `assignments` со снимком шаблона, обязательным `due_at` и необязательным `lesson_id`. Ответы, баллы и файлы привязаны к назначению. Для встроенной работы в демоуроке срок может считаться от даты урока.
- Публичная визитка хранит предметы, описание и ставку в `teacher_profiles`. Окна и заявки находятся в `teacher_slots` и `booking_requests`. Подтверждение бронирует окно и создаёт связь в `teacher_students` в одной транзакции.
- Seed добавляет готовые визитки трём демо-преподавателям, будущие окна и смешанное ДЗ Анне. Повторный запуск сохраняет опубликованные визитки, будущие окна, заявки и сдачи. Когда будущих демоокон больше нет, seed добавляет новые даты.
- «Демо · Видеоурок» связывает Анну и преподавателя математики. При запуске seed завершившийся демоурок снова открывается. Сигналы, состояние участников и сообщения хранятся в таблицах с префиксом `room_`.
- Привязки Telegram и хеши одноразовых кодов хранятся в `telegram_links` и `telegram_link_codes`. Очередь `telegram_jobs` хранит связь с событием, версию привязки и статус доставки. Отмена урока записывается в `assignments.cancelled_at`.

## Команды

В Windows закройте сервер и выполните `.\start.bat --reset-demo` из корня проекта. Команда сохраняет прежний `data/local-lms` в `data/local-lms-backup-*`, создаёт чистую базу и запускает приложение. Сдачи, заявки, чат, сессии и привязки Telegram остаются в сохранённой копии. Настройки `.env.local` действуют и после сброса.

```sh
npm run seed
npm run manage -- demo
npm run manage -- account teacher-example teacher "Имя преподавателя" "Предмет"
npm run manage -- account student-example student "Имя ученика"
npm run manage -- invite student-example teacher-example
```

`invite ID` выдаёт код для входа. Дополнительный ID преподавателя добавляет связь при использовании кода ученика. CLI читает переменные из окружения процесса. Чтобы передать настройки из `.env.local`, используйте `node --env-file=.env.local scripts/manage.mjs <команда>`. Перед запуском CLI на том же каталоге PGlite остановите сервер.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL. Без неё используется PGlite. |
| `OLIMPIK_DATA_DIR` | Каталог PGlite. По умолчанию `data/olimpik-lms`, у `start.bat` — `data/local-lms`. |
| `OLIMPIK_DEMO_LOGIN` | Значение `true` включает кнопки демовхода. |
| `OLIMPIK_SECURE_COOKIES` | Значение `true` включает защищённые cookie при HTTPS. |
| `OLIMPIK_SITE_URL` | Публичный HTTPS-адрес для канонического URL и карты сайта. |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather. Без него сервер запускается с выключенным Telegram. |
| `TELEGRAM_BOT_USERNAME` | Необязательное имя бота. Используется для ссылки, пока имя ещё не получено от Telegram. |
